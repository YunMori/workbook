## Ⅰ. 객관식 해설

**1. 정답 ①** — ECMAScript는 Ecma International이 정의하는 표준화된 스크립트 언어의 **명세**이고, JavaScript는 그 표준을 구현한 구체적인 프로그래밍 언어다. (DOM_Event §1)

**2. 정답 ③** — 식별자는 반드시 문자, `$`, `_`로 시작해야 하며, 따옴표로 감싼다고 숫자로 시작할 수 있는 것이 아니다. (DOM_Event §2)

**3. 정답 ②** — `if` 블록 내부의 `let x = 2`는 **블록 스코프**를 가지므로 블록 안에서는 `2`, 블록 밖에서는 바깥의 `1`이 출력된다. (실행 검증 완료) (DOM_Event §2)

**4. 정답 ④** — 표현식은 익명 함수 사용이 가능하고 호이스팅되지 않으며, **사용이 권장**된다. 선언식은 익명 함수 사용이 불가능하고 호이스팅된다. (DOM_Event §8)

**5. 정답 ①** — 기본 매개변수는 인자가 없거나 `undefined`일 때 기본값으로 초기화되므로 `Hi Anonymous`. 매개변수 개수보다 인자가 많으면 **초과 인자는 사용되지 않으므로** `Hi Alice`. (실행 검증 완료) (DOM_Event §8)

**6. 정답 ③** — `v-on`의 handler 종류는 Inline handlers(이벤트 트리거 시 실행될 JS 코드)와 Method handlers(컴포넌트에 정의된 메서드 이름)다. (Basic_Syntax — v-on)

**7. 정답 ②** — Inline handlers에서 원래 DOM 이벤트에 접근하려면 **`$event`** 변수를 사용해 메서드에 전달한다. 전달 위치는 상관없다. (Basic_Syntax — v-on)

**8. 정답 ④** — `<template>` 태그는 **렌더링되지 않는다**. "보이지 않는 wrapper 역할"을 할 뿐 `<div>`로 변환되지 않는다. (Basic_Syntax — 여러 요소에 대한 v-if 적용)

**9. 정답 ③** — 배열 구문 내에서 객체 구문을 사용한 경우로, `isActive`가 `false`이므로 `active`는 제외되고 `infoClass`의 값인 `text-primary`만 적용된다. (Basic_Syntax — Binding to Arrays)

**10. 정답 ①** — 각 `v-for` 범위는 **상위 범위에 접근할 수 있다**. 따라서 내부 `v-for`에서 외부의 `item.name`을 사용할 수 있다. (Basic_Syntax — 중첩된 v-for)

**11. 정답 ④** — Node.js는 Chrome의 **V8 JavaScript 엔진**을 기반으로 하는 **Server-Side 실행 환경**이다. (Introduction_of_Vue §5)

**12. 정답 ②** — `package.json`과 `package-lock.json`은 **직접 편집을 자제**하고 `npm install 패키지명` 등으로 자동 업데이트하는 것이 안전하다. (Introduction_of_Vue §8, §14)

**13. 정답 ①** — `public`은 소스코드에서 참조되지 않고, 항상 같은 이름을 가지며, import가 필요 없는 정적 파일용(root 절대 경로로 참조). `src/assets`는 **컴포넌트 자체에서 참조하는 내부 파일**을 저장한다. (Introduction_of_Vue §8)

**14. 정답 ③** — 부모가 내려보낸 props를 사용하려면 자식 컴포넌트에서 `defineProps()`를 통한 **명시적인 props 선언**이 필요하다. (component_state_flow §1-2)

**15. 정답 ④** — props는 한 번에 여러 단계 아래로 내려갈 수 있지만, **emit은 한 단계씩** 위로 전달해야 한다. 따라서 중간의 `ParentChild`가 이벤트를 수신한 뒤 다시 발신해야 한다. (component_state_flow §2-6)

**16. 정답 ②** — Lifecycle Hooks 함수들은 반드시 **동기적으로** 작성되어야 Vue가 인스턴스와 자동으로 연결할 수 있다. (component_state_flow §5-1)

**17. 정답 ①** — 여러 source는 **배열**로 전달하고, 콜백도 배열 구조 분해로 받는다. (component_state_flow §4-1)

**18. 정답 ①** — store에서는 공유하지 않는 **private한 상태 속성을 가지지 않는다**. Pinia의 상태를 사용하려면 반드시 반환해야 한다. (state_management §2)

**19. 정답 ③** — 중첩 라우팅은 컴포넌트 간 부모-자식 관계 관점이 아니라 **URL에서의 중첩 관계를 표현하는 관점**으로 바라봐야 한다. (state_management — Nested Routes)

**20. 정답 ④** — `router.push()`는 경로 문자열, `path` 객체, `name`+`params` 객체, `query` 객체 등을 인자로 받는다. `component`를 직접 전달하지 않는다. (state_management — Programmatic Navigation)

**21. 정답 ②** — `then(callback)`은 성공 시 실행되며 이전 작업의 성공 결과를 인자로 받는다. `catch`가 실행되면 **남은 `then`은 중단**되며, axios의 비동기 로직은 **항상 promise 객체를 반환**한다. (Asynchronous_JavaScript — then & catch)

## Ⅱ. 주관식 해설

**22.** 두 가지 방법
```js
// 1) return을 명시적으로 작성
const returnObject1 = () => { return { key: 'value' } }

// 2) 객체를 소괄호로 감싸기
const returnObject2 = () => ({ key: 'value' })
```
- 중괄호만 쓰면 함수 본문 블록으로 해석되기 때문이다.

**23.** `6` / `[1, 2, [3, 4, 5]]`
- 전개 구문은 함수 호출 시 배열을 개별 인자로 **확장**하고(`1+2+3=6`), 나머지 매개변수는 남는 인자를 배열로 **압축**한다. (실행 검증 완료)

**24.** `true` / `false`
- `in` 연산자는 속성이 객체에 존재하는지 여부를 확인한다. `greeting`은 존재하고 `country`는 없다. (실행 검증 완료)

**25.** ㉠ `defineStore` / ㉡ `{ count, doubleCount, increment }`
- `defineStore()`의 첫 인자는 store의 고유 ID(`'counter'`)이며, Setup Store에서는 상태를 사용하려면 반드시 반환해야 한다.

**26.**
- JavaScript 자체는 Single Thread이므로, 비동기 처리를 할 수 있도록 도와주는 **실행 환경(Runtime)** 이 필요하며 비동기 관련 작업은 그 환경에서 처리된다.
- 두 가지 실행 환경: **브라우저(Browser)**, **Node**

**27.**
```js
const age = 100
const message = `홍길동은 ${age}세입니다.`
```
- Backtick(`` ` ``)과 `${expression}` 표기를 사용한다.

## Ⅲ. 서술형 채점 기준

**28. (5점)**

| 배점 | 채점 요소 |
|---|---|
| 2점 | 1단계 — 조작하고자 하는 요소를 **선택(탐색)**: `document.querySelector()`, `document.querySelectorAll()` |
| 2점 | 2단계 — 선택된 요소의 콘텐츠 또는 속성을 **조작**: `classList.add/remove/toggle`, `getAttribute/setAttribute/removeAttribute`, `textContent`, `createElement/appendChild/removeChild` 등 |
| 1점 | "웹 페이지를 동적으로 만들기 == 웹 페이지를 조작하기"라는 전제 및 조작 범주(속성 / HTML 콘텐츠 / DOM 요소 / 스타일) 언급 |

**모범 답안**
> 웹 페이지를 동적으로 만든다는 것은 곧 웹 페이지를 조작하는 것이며, DOM 조작은 항상 두 단계로 이루어진다. **1단계는 조작하고자 하는 요소를 선택(또는 탐색)하는 것**으로, `document.querySelector(selector)`로 조건에 맞는 첫 번째 요소 하나를, `document.querySelectorAll(selector)`로 조건에 맞는 여러 요소를 NodeList로 선택한다. **2단계는 선택된 요소의 콘텐츠 또는 속성을 조작하는 것**이다. 클래스 속성은 `element.classList.add()`, `remove()`, `toggle()`로 조작하고, 일반 속성은 `getAttribute()`, `setAttribute(name, value)`, `removeAttribute()`로 조회·설정·제거한다. HTML 콘텐츠는 `textContent` 속성으로 변경하며, DOM 요소 자체는 `document.createElement(tagName)`으로 생성하고 `appendChild()`로 추가, `removeChild()`로 제거한다.

**29. (4점)**

| 배점 | 채점 요소 |
|---|---|
| 1.5점 | 기존 방식: form을 채워 서버로 제출 → 서버가 데이터 처리 후 **새로운 웹페이지를 작성**해 응답 → 매 요청마다 새로고침 발생, 중복 코드 전송으로 대역폭 낭비 |
| 1.5점 | AJAX 방식: XHR 객체 생성 및 요청 → 서버는 새 페이지가 아니라 **필요한 부분의 데이터만**(JSON 등) 응답 → 기존 페이지 일부만 수정(새로고침 없음) |
| 1점 | 이점: 교환 데이터량·처리량 감소, 페이지 일부 로드 중에도 코드 계속 실행(비동기), 사용자 작업을 방해하지 않음 |

**모범 답안**
> 기존 방식에서는 클라이언트가 form을 채워 서버로 제출하면, 서버가 요청 내용에 따라 데이터를 처리한 뒤 **새로운 웹페이지 전체를 작성하여 응답**한다. 그 결과 모든 요청마다 새 페이지를 받으므로 계속해서 새로고침이 발생하고, 기존 페이지와 유사한 내용을 다시 전송받으면서 중복 코드로 인해 대역폭을 낭비하게 된다. 반면 AJAX 방식에서는 XHR 객체를 생성해 요청을 보내고, 서버는 새로운 페이지를 만들지 않고 **필요한 부분에 대한 데이터만**(JSON 등) 처리해 응답한다. 클라이언트는 받은 데이터로 기존 페이지의 일부 DOM만 갱신하므로 새로고침이 발생하지 않는다. 이로써 서버에서 모두 처리되던 작업의 일부가 클라이언트로 옮겨져 교환되는 데이터량과 처리량이 줄어들고, 페이지 일부가 다시 로드되는 동안에도 코드가 계속 실행되어 사용자의 작업을 방해하지 않는다.

**30. (4점)**

| 배점 | 채점 요소 |
|---|---|
| 1.5점 | SSR Routing: **서버 측**에서 수행. 서버가 URL 경로 기반으로 응답 전송, 링크 클릭 시 HTML 응답을 받아 **전체 페이지를 다시 로드** |
| 1.5점 | CSR Routing: **클라이언트 측**에서 수행. JavaScript가 새 데이터를 동적으로 가져와 **전체 페이지를 다시 로드하지 않음** |
| 1점 | Router가 없으면: URL로 페이지 변화 감지 불가, 새로고침 시 첫 페이지로 복귀, 링크 공유 시 첫 페이지만 공유, 뒤로 가기 사용 불가 |

**모범 답안**
> SSR에서의 Routing은 **서버 측**에서 수행된다. 서버가 사용자가 방문한 URL 경로를 기반으로 응답을 전송하며, 링크를 클릭하면 브라우저는 서버로부터 HTML 응답을 받아 새 HTML로 **전체 페이지를 다시 로드**한다. 반면 CSR에서의 Routing은 **클라이언트 측**에서 수행되며, 클라이언트의 JavaScript가 새 데이터를 동적으로 가져와 화면을 갱신하므로 전체 페이지를 다시 로드하지 않는다. SPA에서 Routing이 없다면 URL이 하나뿐이므로 사용자가 URL을 통해 페이지 변화를 감지할 수 없고, 새로고침 시 처음 페이지로 되돌아가며, 링크를 공유해도 첫 페이지만 공유되고, 브라우저의 뒤로 가기 기능도 사용할 수 없다. 따라서 페이지는 1개이지만 주소에 따라 여러 컴포넌트를 새로 렌더링해 마치 여러 페이지를 사용하는 것처럼 보이도록 Vue Router가 필요하다.

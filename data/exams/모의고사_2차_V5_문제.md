**2. [기초]** 객체(Object)의 구조에 대한 설명으로 옳은 것은?

② `key`는 모든 자료형이 허용되고, `value`는 문자형만 허용된다.

**3. [응용]** 반복문의 특징 연결로 **옳지 않은** 것은?

① `for...in` — object 순회, 블록 스코프
② `for...of` — iterable 순회, 블록 스코프
③ `for...in` — 배열 순회 시 인덱스 순서를 항상 보장하므로 배열에 사용 권장
④ `for` — `i`를 재할당하므로 `const` 대신 `let`을 사용

③ 이벤트 핸들러를 제거한다.
④ 이벤트를 상위 요소로 강제 전파한다.

**8. [기초]** `v-if`와 `v-show`의 특성 비교로 옳은 것은?

① `v-if` — Expensive initial load, cheap toggle / `v-show` — Cheap initial load, expensive toggle

③ 둘 다 초기 렌더링 비용과 토글 비용이 동일하다.

**9. [응용]** `<select v-model="selected">`에서 `selected`의 초기 값이 어떤 `option`과도 일치하지 않는 경우 렌더링 결과는?

① `select` 요소가 "선택되지 않은(unselected)" 상태로 렌더링된다.
② 첫 번째 `option`이 자동으로 선택된다.
③ `select` 요소 전체가 DOM에서 제거된다.
④ 콘솔에 경고가 출력되고 마지막 `option`이 선택된다.

**10. [응용]** 배열 메서드 분류로 **옳지 않은** 것은?

① 변화 메서드(원본 배열 변경): `push()`, `pop()`, `splice()`
② 배열 교체(새 배열 반환): `filter()`, `concat()`, `slice()`
③ `unshift()`, `shift()`는 원본 배열을 변경한다.
④ `sort()`와 `reverse()`는 새 배열을 반환하므로 `computed` 내에서 안전하게 사용할 수 있다.

**11. [기초]** Component에 대한 설명으로 **옳지 않은** 것은?

① 재사용 가능한 코드 블록이다.
② 하나의 애플리케이션에는 Root 컴포넌트가 여러 개 필요하다.
③ UI를 독립적이고 재사용 가능한 일부분으로 분할할 수 있다.
④ 애플리케이션은 자연스럽게 중첩된 Component의 트리 형태로 구성된다.

---

**12. [기초]** Module과 Bundler에 대한 설명으로 **옳지 않은** 것은?

① 모듈은 프로그램을 구성하는 독립적인 코드 블록이며, `*.js` 파일 하나가 하나의 모듈이다.
② 모듈 개수가 증가하면 성능 병목과 의존성 문제가 발생할 수 있다.
③ Bundler의 역할은 의존성 관리에 한정되며 코드 최적화는 수행하지 않는다.
④ Bundler는 여러 모듈과 파일을 하나(혹은 여러 개)의 번들로 묶어 최적화한다.

---

**13. [응용]** `<script setup>` 블록에 대한 설명으로 **옳지 않은** 것은?

① 각 `*.vue` 파일은 `<script setup>` 블록을 하나만 포함할 수 있다.
② 컴포넌트의 `setup()` 함수로 사용되며 컴포넌트의 각 인스턴스에 대해 실행된다.
③ 선언된 변수 및 함수는 동일한 컴포넌트의 템플릿에서 자동으로 사용 가능하다.
④ 템플릿에서 사용하려면 반드시 객체 형태로 `return` 해야 한다.

---

**14. [기초]** `<style scoped>`를 사용했을 때의 효과로 옳은 것은?

① 해당 컴포넌트 내부의 스타일이 현재 컴포넌트 내부 요소에게만 적용되도록 범위를 제한한다.
② 해당 스타일이 전역(모든 컴포넌트)에 적용된다.
③ 자식 컴포넌트의 모든 요소에 부모의 스타일이 강제로 적용된다.
④ CSS 우선순위가 항상 `!important`로 처리된다.

**15. [응용]** props 선언 시 "객체 선언 문법"을 권장하는 이유로 **옳지 않은** 것은?

① 컴포넌트를 가독성 좋게 문서화하는 데 도움이 된다.
② 배열 선언보다 코드 길이가 짧아 유지보수가 쉽다.
③ 다른 개발자가 잘못된 유형을 전달할 때 브라우저 콘솔에 경고를 출력하도록 한다.
④ props에 대한 유효성 검사로 활용할 수 있다.

**16. [응용]** 다음 props 선언에 대한 설명으로 **옳지 않은** 것은?

```js
defineProps({
  propB: [String, Number],
  propC: { type: String, required: true },
  propD: { type: Number, default: 10 }
})
```

① `propB`는 String 또는 Number 타입을 허용한다.
② `propC`는 String 타입이며 필수 항목이다.
③ `propD`는 `default`가 있으므로 `required: true`와 동일하게 동작한다.
④ `propD`는 값이 전달되지 않으면 `10`이 사용된다.

④ 계산된 값은 읽기 전용으로 취급해야 하며, 새 값을 얻으려면 의존하는 데이터를 업데이트해야 한다.

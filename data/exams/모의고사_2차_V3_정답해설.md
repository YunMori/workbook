## Ⅰ. 객관식 해설

**1. 정답 ②** — `var`는 **함수 스코프**, `let`과 `const`는 **블록 스코프**를 가진다. (DOM_Event §2, §8 참고)

**2. 정답 ④** — `typeof null`이 `"object"`인 것은 설계 당시의 버그를 하위 호환 때문에 고치지 않은 결과다. ①②는 설명이 서로 바뀌었고, ③은 틀리다(둘 다 항상 `false`로 평가). (DOM_Event §3)

**3. 정답 ③** — 논리 연산자는 **단축 평가**를 지원하며 boolean이 아니라 피연산자 값을 반환한다. `1&&0` → `0`, `4&&7` → `7`, `0||1` → `1`, `4||7` → `4`. (실행 검증 완료) (DOM_Event §4)

**4. 정답 ①** — 요소를 생성하는 것은 `document.createElement(tagName)`이다. `Node.appendChild()`는 특정 부모의 마지막 자식으로 노드를 **삽입**한다. (DOM_Event §7)

**5. 정답 ②** — `var`로 선언된 변수는 hoisted 되면서 `undefined`로 초기화되므로 선언 이전 접근 시 `undefined`가 반환된다(실행 검증 완료). `let`/`const`는 `ReferenceError: Cannot access ... before initialization`이 발생하고, 함수 표현식은 호이스팅되지 않는다. (DOM_Event §8 참고)

**6. 정답 ④** — Template Syntax 4종류는 Text Interpolation, Raw HTML, Attribute Bindings, JavaScript Expressions. (Basic_Syntax — Template Syntax)

**7. 정답 ③** — `:style` 객체 바인딩에서 camelCase 키(`fontSize`)는 실제 CSS 속성명(`font-size`)으로 변환되어 렌더링된다. (Basic_Syntax — Binding Inline Styles)

**8. 정답 ①** — `v-model`은 form input 요소 또는 컴포넌트에서 **양방향 바인딩**을 만든다. text뿐 아니라 checkbox, radio, select 등에도 사용 가능하다. (Basic_Syntax — v-model)

**9. 정답 ④** — 객체 반복 시 별칭 순서는 `(value, key, index)`이고, 템플릿은 `{{ index }} / {{ key }} / {{ value }}` 순으로 출력하므로 `0 / name / Cathy`, `1 / age / 30`이 된다. (Basic_Syntax — v-for)

**10. 정답 ②** — 대괄호 안에 작성하는 이름은 반드시 소문자로만 구성해야 한다. 브라우저가 속성 이름을 소문자로 강제 변환하기 때문이다. (Basic_Syntax — Dynamic attribute name)

**11. 정답 ①** — Vue의 2가지 핵심 기능은 **선언적 렌더링**과 **반응성**이다. (Introduction_of_Vue §2-1)

**12. 정답 ③** — 우선순위 A(필수, Essential)에 대한 설명이다. (Introduction_of_Vue §2-2)

**13. 정답 ②** — 각 앱 인스턴스에 대해 `mount()`는 **한 번만** 호출할 수 있다. (Introduction_of_Vue §3-1)

**14. 정답 ④** — Single Root Element는 가독성, 스타일링, 컴포넌트 관리를 위해 각 컴포넌트에 최상단 HTML 요소를 작성하는 **권장 사항**이다(강제 오류가 아님). (Introduction_of_Vue §12)

**15. 정답 ①** — 자식은 props를 변경할 수 없으며, 변경은 부모에서만 이루어진다. (component_state_flow §1-1)

**16. 정답 ③** — `emit('emitArgs', 1, 2, 3)`으로 전달된 추가 인자가 부모의 `...args`에 배열로 모여 `[1, 2, 3]`이 출력된다. (component_state_flow §2-4)

**17. 정답 ②** — 강의자료가 제시한 Virtual DOM 패턴의 장점은 효율성, 반응성, 추상화 세 가지다. (component_state_flow §5-2)

**18. 정답 ②** — Virtual DOM 영역에서는 `querySelector`, `createElement`, `addEventListener` 등 실제 DOM 접근 메서드 사용을 금지하며, 템플릿의 `ref` 속성과 같은 이름의 `ref(null)` 변수, 그리고 Lifecycle Hooks를 사용해 간접적으로 접근한다. (component_state_flow §5-2)

**19. 정답 ④** — ④는 SSR/MPA에 대한 설명이다. SPA에서 Routing이 없을 때의 문제는 URL로 페이지 변화 감지 불가, 새로고침 시 첫 페이지로 복귀, 링크 공유 시 첫 페이지만 공유, 뒤로 가기 사용 불가 등이다. (state_management §3)

**20. 정답 ③** — `params` 객체의 key 이름은 `index.js`에 지정한 매개변수 이름과 **같아야 한다**. (state_management — Dynamic Route Matching)

**21. 정답 ①** — Task Queue는 **FIFO** 구조이며, Event Loop는 가장 오래된(먼저 들어온) 작업을 Call Stack으로 보낸다. (Asynchronous_JavaScript — 비동기 처리 동작 요소)

## Ⅱ. 주관식 해설

**22.** 다음 중 3가지 (모두 정답 인정)
1. 숫자로서 읽을 수 없음 — `Number(undefined)`
2. 결과가 허수인 수학 계산식 — `Math.sqrt(-1)`
3. 피연산자가 NaN — `7 ** NaN`
4. 정의할 수 없는 계산식 — `0 * Infinity`
5. 문자열을 포함하면서 덧셈이 아닌 계산식 — `'가' / 3`

**23.** `[5, 5, 5]` / `undefined`
- `map()`은 콜백 결과를 모은 **새 배열**을 반환하고, `forEach()`는 **반환 값이 없다(`undefined`)**. (실행 검증 완료)

**24.** **Asynchronous JavaScript and XML**

**25.** `() => import('../views/AboutView.vue')`
- 앱 로드 시점이 아니라 해당 경로를 **처음 방문할 때** 컴포넌트를 로드한다.

**26.**
- (1) 단순 호출 → **전역 객체(`window`)**
- (2) 메서드 호출 → **메서드를 호출한 객체(`myObj`)**
- JavaScript의 `this`는 함수가 "호출되는 방식"에 따라 동적으로 결정된다.

**27.** `['name', 'age']` / `['Alice', 30]`
- `Object.keys()`는 키 배열, `Object.values()`는 값 배열을 반환한다. (실행 검증 완료)

## Ⅲ. 서술형 채점 기준

**28. (5점)**

| 배점 | 채점 요소 |
|---|---|
| 2점 | SFC = 컴포넌트의 템플릿, 로직, 스타일을 하나의 파일로 묶어낸 특수한 파일 형식(`*.vue`), HTML·CSS·JS를 단일 파일로 합친 것 |
| 3점 | 세 블록 각 1점: `<template>`(뷰/화면 구조, 파일당 하나만), `<script setup>`(로직, `setup()` 함수로 사용되며 변수·함수가 템플릿에서 자동 사용 가능), `<style scoped>`(스타일, `scoped` 지정 시 현재 컴포넌트에만 적용) |

**모범 답안**
> SFC(Single-File Components)는 컴포넌트의 **템플릿, 로직, 스타일을 하나의 파일로 묶어낸 특수한 파일 형식(`*.vue`)** 으로, HTML·CSS·JavaScript를 단일 파일로 합친 것이다. `<template>` 블록은 컴포넌트의 뷰(화면 구조)를 담당하며 각 파일에 하나만 포함될 수 있다. `<script setup>` 블록은 컴포넌트의 로직을 담당하고 컴포넌트의 `setup()` 함수로 사용되며, 이 안에서 선언한 변수와 함수는 동일 컴포넌트의 템플릿에서 자동으로 사용할 수 있다. `<style>` 블록은 스타일을 담당하고 여러 개 작성할 수 있으며, `scoped`를 지정하면 해당 CSS가 현재 컴포넌트에만 적용된다. 블록 작성 순서는 상관없으나 일반적으로 template → script → style 순으로 작성한다.

**29. (4점)**

| 배점 | 채점 요소 |
|---|---|
| 2점 | 콜백 지옥 원인: 비동기 작업의 결과를 받아 다음 작업을 수행하는 패턴이 반복되며 콜백이 계속 중첩됨 → 피라미드 형태("Pyramid of doom"), 가독성 저하·유지보수 어려움 |
| 2점 | Promise chaining 장점 2개 이상: 가독성(순서·의존 관계 명확), 에러 처리(단계별 분할 처리), 유연성(단계마다 데이터 가공/다른 비동기 작업), 코드 관리 용이 |

**모범 답안**
> 비동기 콜백은 어떤 기능의 실행 결과를 받아 다른 기능을 수행하기 위해 사용되는데, "요청 결과가 나오면 첫 번째 콜백 실행 → 첫 번째 콜백이 끝나면 두 번째 콜백 실행 → …"이라는 패턴이 반복되면서 콜백이 계속 중첩된다. 그 결과 코드 형태가 피라미드처럼 깊어지는 **콜백 지옥(Pyramid of doom)** 이 발생하고, 가독성이 나빠지며 유지 보수가 어려워진다. Promise는 이 문제를 해결하기 위해 등장한 객체로, `then()`으로 성공, `catch()`로 실패를 처리하며 체이닝할 수 있다. `then` 체이닝의 장점은 첫째 **가독성** — 비동기 작업의 순서와 의존 관계를 평면적으로 명확히 표현할 수 있고, 둘째 **에러 처리** — 각 단계에서 발생하는 에러를 분할해 처리할 수 있으며, 셋째 **유연성** — 각 단계마다 데이터를 가공하거나 다른 비동기 작업을 수행할 수 있고, 넷째 **코드 관리** — 비동기 작업을 분리해 구성하므로 관리가 용이하다는 점이다.

**30. (4점)**

| 배점 | 채점 요소 |
|---|---|
| 2점 | `key`는 Vue의 내부 **가상 DOM 알고리즘이 이전 노드 목록과 새 노드 목록을 비교할 때 각 node를 식별**하는 용도. 내부 컴포넌트 상태를 일관되게 하여 데이터의 예측 가능한 행동을 유지 |
| 1점 | `key`는 각 요소의 고유한 값(number/string)이어야 함. 권장: DB 고유 ID, UUID |
| 1점 | 인덱스는 식별자가 아니라 **항목의 위치**만 나타내므로, 배열 끝이 아닌 위치에 새 요소가 삽입되면 이미 반복된 구성 요소의 데이터가 함께 업데이트되지 않음 |

**모범 답안**
> Vue의 내부 가상 DOM 알고리즘은 이전 노드 목록과 새 노드 목록을 비교할 때 각 node를 식별하기 위해 `key`를 사용한다. 따라서 `v-for`에는 반드시 `key`를 함께 작성해야 내부 컴포넌트의 상태가 일관되게 유지되고 데이터가 예측 가능하게 동작한다. `key`는 `number` 또는 `string` 타입이면서 각 요소를 고유하게 식별할 수 있는 값이어야 하며, 데이터베이스의 고유 ID나 UUID 같은 항목 고유 식별자가 권장된다. 반면 **배열 인덱스**를 `key`로 사용하면 안 되는데, 인덱스는 식별자가 아니라 배열에서의 **항목 위치**만 나타내기 때문이다. 새 요소가 배열의 끝이 아닌 위치에 삽입되면 그 이후 항목들의 인덱스가 모두 밀리면서, 이미 렌더링된 구성 요소의 데이터가 함께 업데이트되지 않는 문제가 발생한다. 객체 자체를 `key`로 쓰는 것도 피해야 한다.

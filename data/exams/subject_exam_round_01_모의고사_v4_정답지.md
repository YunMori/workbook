## 객관식 해설

**1. 정답 ④** — 데이터베이스 설계는 Backend/서버 영역이다. Frontend는 UI/UX 개발 및 사용자 상호작용 담당이다. (Introduction_of_Vue §1)

**2. 정답 ①** — 슬라이드는 "웹에서 하는 일이 많아졌다"와 "다루는 데이터가 많아졌다"를 강조하며 client-side framework의 필요성을 설명했다. (Introduction_of_Vue §1)

**3. 정답 ③** — SPA는 단일 페이지로 구성되어 사용자가 상호작용할 때마다 페이지 전체를 새로 로드하지 않고 필요한 부분만 동적으로 갱신한다. (Introduction_of_Vue §1)

**4. 정답 ②** — SPA는 대부분 JavaScript 프레임워크로 클라이언트 측에서 UI/렌더링을 관리하는 CSR 방식을 사용한다. (Introduction_of_Vue §1)

**5. 정답 ②** — CSR은 최소한의 HTML+JS를 먼저 받고, 이후 클라이언트 JS가 DOM을 렌더링하며, 이후 통신은 Ajax로 JSON 데이터만 주고받는다. (Introduction_of_Vue §1)

**6. 정답 ②** — CSR은 JS 다운로드·파싱·실행 전까지 렌더링되지 않아 초기 로드가 느리고, SEO 문제가 있다. (Introduction_of_Vue §1)

**7. 정답 ②** — MPA는 SPA와 대비되는 개념으로, 페이지 이동 시마다 서버로부터 새로운 HTML 파일을 각각 로드한다. (Introduction_of_Vue §1)

**8. 정답 ①** — Vue는 Angular 개발팀 출신인 Evan You가 2014년 발표했다. (Introduction_of_Vue §2)

**9. 정답 ②** — 최신 버전은 Vue 3(2024)이며, Vue 2 문서로 잘못 접속하지 않도록 강조 표시되어 있었다. (Introduction_of_Vue §2)

**10. 정답 ①** — Vue의 핵심 기능은 선언적 렌더링(Declarative Rendering)과 반응성(Reactivity)이다. (Introduction_of_Vue §2)

**11. 정답 ①** — A등급(Essential)은 오류를 방지하기 위해 어떤 경우에도 학습하고 준수해야 하는 필수 규칙이다. (Introduction_of_Vue §2)

**12. 정답 ①** — Vue를 사용하는 방법으로 CDN 방식과 NPM 설치 방식 두 가지가 소개되었다. (Introduction_of_Vue §3)

**13. 정답 ②** — 모든 Vue 애플리케이션은 `createApp` 함수로 새 Application instance를 생성하며 시작한다. (Introduction_of_Vue §3)

**14. 정답 ②** — 각 앱 인스턴스에 대해 `mount()`는 한 번만 호출 가능하다(예: `app.mount('#app')`). (Introduction_of_Vue §3)

**15. 정답 ③** — setup에서 준비한 값을 반환(return)하면 템플릿에서 바로 사용할 수 있다. (Introduction_of_Vue §3)

**16. 정답 ①** — ref는 reactive reference의 줄임말로, 반응형 상태를 선언하며 `.value` 속성이 있는 ref 객체로 값을 래핑하여 반환한다. (Introduction_of_Vue §4)

**17. 정답 ②** — `console.log(message)`는 ref 객체 자체를 출력하며, 실제 값은 `console.log(message.value)`로 접근해야 한다. (Introduction_of_Vue §4)

**18. 정답 ②** — 템플릿에서는 편의상 ref가 자동으로 unwrap되므로 `.value`를 작성할 필요가 없다. (Introduction_of_Vue §4)

**19. 정답 ①** — createApp()에 전달되는 객체는 Vue 컴포넌트이며, 컴포넌트의 상태는 setup() 함수 내에서 선언되고 객체로 반환되어야 한다. (Introduction_of_Vue §4)

**20. 정답 ①** — `{{ }}`는 Mustache syntax(콧수염 구문)라고 부르며, 반응형 데이터를 기반으로 동적 텍스트를 렌더링한다. (Introduction_of_Vue §4)

**21. 정답 ②** — 예시로 `{{ message.split('').reverse().join('') }}`처럼 유효한 JS 표현식을 사용할 수 있다. (Introduction_of_Vue §4)

**22. 정답 ②** — 슬라이드는 `v-on` directive를 사용해 DOM 이벤트를 수신한다고 소개했다(예: `v-on:click="increment"`). (Introduction_of_Vue §4)

**23. 정답 ②** — JS는 일반 변수(원시값)의 접근·변형을 감지할 수 없어, Vue는 객체 타입인 ref로 값을 감싸 의존성 추적 기반의 반응형 시스템을 구현한다. (Introduction_of_Vue §4)

**24. 정답 ④** — 애플리케이션은 여러 Component가 중첩된 트리 형태로 구성된다. (Introduction_of_Vue §5)

**25. 정답 ②** — SFC는 HTML, CSS, JavaScript를 하나의 `*.vue` 파일로 합친 형식으로, `<template>`, `<script>`, `<style>` 블록으로 구성된다. (Introduction_of_Vue §5)

**26. 정답 ②** — 작성 순서는 상관없으나 일반적으로 template → script → style 순서로 작성한다. (Introduction_of_Vue §5)

**27. 정답 ②** — 각 `*.vue` 파일은 최상위 `<template>` 블록 하나, `<script setup>` 블록 하나만 포함할 수 있다. (Introduction_of_Vue §5)

**28. 정답 ②** — `*.vue` 파일에는 여러 `<style>` 태그를 포함할 수 있으며, `scoped`가 지정되면 CSS는 현재 컴포넌트에만 적용된다. (Introduction_of_Vue §5)

**29. 정답 ②** — Vue SFC는 컴파일러를 통해 컴파일된 후 Vite 같은 공식 빌드 도구로 빌드되어야 한다. (Introduction_of_Vue §5)

**30. 정답 ②** — Node.js는 Chrome의 V8 엔진 기반 서버 사이드 실행 환경으로, 브라우저 밖에서도 JS를 실행 가능하게 한다. (Introduction_of_Vue §6)

**31. 정답 ②** — 모듈 개수 급증으로 성능 병목, 의존성 문제 등이 발생하며 이를 해결하기 위해 Bundler가 필요해졌다. (Introduction_of_Vue §6)

**32. 정답 ②** — Vite는 Rollup이라는 Bundler를 사용한다. (Introduction_of_Vue §6, §7)

**33. 정답 ③** — `npm run dev` 실행 시 "VITE v7.1.2 ready in 5825 ms"와 함께 Local: http://localhost:5173/ 이 출력되었다. (Introduction_of_Vue §7)

**34. 정답 ②** — 슬라이드에서 Vue DevTools 단축키로 `Alt + Shift + D`가 소개되었다. (Introduction_of_Vue §7)

**35. 정답 ③** — node_modules는 외부 패키지 의존성 모듈을 저장/관리하는 디렉토리로, `.gitignore`에 작성되어 버전관리에서 제외된다. (Introduction_of_Vue §8)

**36. 정답 ①** — package.json은 프로젝트 메타정보와 의존성 목록을, package-lock.json은 실제 설치 버전/의존성 관계를 기록한다. (Introduction_of_Vue §8)

**37. 정답 ②** — public 디렉토리는 정적 파일 위치로 import가 불필요하며, 예를 들어 `public/icon.png`는 `/icon.png`로 참조한다. (Introduction_of_Vue §8)

**38. 정답 ①** — index.html은 Vue 앱의 entry point로, Root 컴포넌트(App.vue)가 이 페이지에 mount되며 이 구조가 Vue 앱이 SPA인 이유이다. (Introduction_of_Vue §9)

**39. 정답 ②** — 컴포넌트 사용은 ① 컴포넌트 파일 생성 ② 컴포넌트 등록(import) 의 2단계로 진행된다. (Introduction_of_Vue §10)

**40. 정답 ③** — `import MyComponent from '@/components/MyComponent.vue'`에서 `@`는 `src/` 경로를 뜻하는 약어이다. (Introduction_of_Vue §10)

## 주관식 해설

**41.** Client-side framework(클라이언트 사이드 프레임워크)

- Vue, React, Angular와 같이 클라이언트 측에서 UI와 상호작용을 개발하기 위해 사용되는 JS 기반 프레임워크를 뜻한다.

**42.** SSR(Server-side Rendering)

- CSR과 대비되는 개념으로, 서버가 모든 데이터가 담긴 완성된 HTML을 클라이언트에 전달한다.

**43.** Evan You

- Angular 개발팀 출신으로 2014년 Vue를 발표했다.

**44.** 선언적 렌더링(Declarative Rendering)

- Vue의 두 핵심 기능(선언적 렌더링, 반응성) 중 하나이다.

**45.** 구조분해할당(Destructuring assignment)

- `const { createApp } = Vue`는 Vue 객체에서 createApp 함수를 구조분해할당으로 추출한다.

**46.** Root Component(루트 컴포넌트)

- createApp 함수에 전달되는 객체가 Root Component이며, 하위 컴포넌트를 포함할 수 있다.

**47.** `.value`

- ref는 `.value` 속성이 있는 객체로 값을 래핑하여 반환하며, JS 코드에서는 `.value`로 접근해야 한다.

**48.** reactive reference(반응형 참조)

- ref === reactive reference로, 반응형을 가지는 참조 변수를 만드는 함수이다.

**49.** Mustache syntax(콧수염 구문)

- 반응형 데이터를 기반으로 동적 텍스트를 렌더링하는 템플릿 구문이다.

**50.** `v-on`

- `v-on` directive는 DOM 이벤트를 수신하며, 이벤트 핸들러 함수 내에서 반응형 변수를 변경해 상태를 업데이트한다.

**51.** Single-File Component(SFC), 확장자 `.vue`

- SFC는 `<template>`, `<script>`, `<style>` 세 가지 최상위 블록으로 구성된 `*.vue` 파일이다.

**52.** Vue SFC Playground (https://play.vuejs.org/)

- 이 사이트에서 Vue 컴포넌트 코드를 작성하고 미리볼 수 있다고 소개되었다.

**53.** V8 (V8 JavaScript 엔진)

- Node.js는 Chrome의 V8 JavaScript 엔진 기반의 Server-Side 실행 환경이다.

**54.** NPM(Node Package Manager)

- Node.js의 영향으로 NPM을 활용한 패키지 공유/재사용이 가능해졌다.

**55.** Module(모듈)

- 애플리케이션 규모/복잡도 증가로 파일을 여러 개의 모듈로 분리하게 되었다.

**56.** Bundler(번들러)

- 모듈 개수 급증으로 인한 성능 병목·의존성 문제를 해결하기 위해 등장했으며, 이 작업을 Bundling이라 한다.

**57.** `main.js` (src/main.js)

- src/main.js는 Vue 인스턴스 생성 및 애플리케이션 초기화, 라이브러리 import 및 전역 설정을 수행한다.

**58.** `App.vue`

- src/App.vue는 Vue 앱의 최상위 Root 컴포넌트이다.

**59.** Option API(옵션 API)

- Option API는 Vue2 방식이며 Vue3에서도 지원된다. 반대는 Composition API(Vue3 권장 방식)이다.

**60.** 레이아웃(배치) 제어 목적

- Vue는 부모 컴포넌트가 자식 컴포넌트의 최상위 요소 스타일을 제어할 수 있어야 레이아웃 목적을 쉽게 달성할 수 있다고 판단했기 때문이다.

## 서술형 채점 기준

**61**

| 배점 | 채점 요소                                                                                          |
| ---- | --------------------------------------------------------------------------------------------------- |
| 1점  | 장점 ①: 페이지 이동 시 서버에 매번 새 HTML을 요청하지 않아 페이지 전환이 빠르고 서버 부하가 적음    |
| 1점  | 장점 ②: 새로고침 없는 네이티브 앱과 유사한 UX 제공 (또는 Frontend/Backend 역할 분리)                |
| 1점  | 단점 ①: JS 다운로드·파싱·실행 전까지 화면이 렌더링되지 않아 초기 로드 속도가 느림                    |
| 1점  | 단점 ②: 콘텐츠가 나중에 그려져 검색엔진이 분석하기 어려운 SEO 문제                                  |

**모범 답안**

> CSR의 장점은 다음과 같다. 첫째, 페이지 이동 시 서버에 매번 새 HTML을 요청하지 않아 페이지 전환이 빠르고 서버 부하가 적다. 둘째, 새로고침 없는 네이티브 앱과 유사한 사용자 경험(UX)을 제공한다. 셋째, Frontend(UI 렌더링·상호작용)와 Backend(데이터·API)의 역할이 명확히 분리된다. 반면 단점은, 첫째 JS 파일을 다운로드·파싱·실행하기 전까지는 화면이 렌더링되지 않아 초기 로드 속도가 느리다는 점이다. 둘째, 콘텐츠가 JS 실행 이후 나중에 그려지기 때문에 검색엔진이 콘텐츠를 분석하기 어려운 SEO 문제가 있다.

**62**

| 배점 | 채점 요소                                                                                                  |
| ---- | ------------------------------------------------------------------------------------------------------------ |
| 2점  | 선언적 렌더링: 표준 HTML을 확장한 템플릿 구문으로 JS 상태 기반으로 화면 HTML을 선언적으로 작성하는 기능     |
| 2점  | 반응성: JS 상태 변경을 Vue가 자동 추적하여 의존하는 DOM을 자동 업데이트하는 기능                            |

**모범 답안**

> 선언적 렌더링(Declarative Rendering)은 표준 HTML을 확장한 템플릿 구문을 사용해, JS 상태(데이터)를 기반으로 화면에 출력될 HTML을 선언적으로 작성하는 기능이다. 즉 "무엇을 보여줄지"를 데이터와 템플릿으로 표현하면 Vue가 알아서 DOM에 반영한다. 반응성(Reactivity)은 JS 상태(데이터)의 변경을 Vue가 자동으로 추적하고, 변경이 발생하면 그에 의존하는 DOM을 자동으로 업데이트하는 기능이다. 개발자가 직접 DOM을 조작하지 않아도 상태 변화가 화면에 즉시 반영된다.

**63**

| 배점 | 채점 요소                                                                          |
| ---- | ------------------------------------------------------------------------------------ |
| 2점  | JS 코드 내부에서는 `.value`로 접근해야 함을 예시 코드와 함께 설명                    |
| 2점  | 템플릿에서는 자동 unwrap되어 `.value` 없이 사용 가능함을 예시 코드와 함께 설명       |

**모범 답안**

> `ref()`는 값을 `.value` 속성을 가진 객체로 래핑하여 반환한다. 따라서 JS 코드(setup 함수 등) 내부에서는 반드시 `.value`를 통해 접근해야 한다.
>
> ```js
> const count = ref(0)
> console.log(count)        // ref 객체 출력
> console.log(count.value)  // 0 출력
> count.value++              // 값 변경 시 .value 사용
> ```
>
> 반면 템플릿에서는 편의를 위해 ref가 자동으로 unwrap되므로 `.value`를 작성할 필요가 없다.
>
> ```html
> <div>{{ count }}</div>  <!-- .value 없이 바로 사용 -->
> ```

**64**

| 배점 | 채점 요소                                                                             |
| ---- | ---------------------------------------------------------------------------------------- |
| 1.5점 | `<template>`: 컴포넌트의 뷰(마크업)를 정의하며 하나만 포함 가능                        |
| 1.5점 | `<script setup>`: 컴포넌트의 로직(상태, 함수 등)을 정의하며 setup() 역할, 하나만 포함  |
| 1점  | `<style>`: 컴포넌트의 스타일(CSS)을 정의하며 여러 개 작성 가능, scoped로 범위 제한 가능 |

**모범 답안**

> Vue SFC는 `<template>`, `<script>`(또는 `<script setup>`), `<style>` 세 가지 최상위 블록으로 구성된다. `<template>`은 컴포넌트의 뷰(마크업)를 정의하며 하나의 파일에 하나만 포함될 수 있다. `<script setup>`은 컴포넌트의 로직(상태, 함수 등)을 정의하며 컴포넌트의 setup() 함수 역할을 하고, 마찬가지로 하나만 포함될 수 있다. `<style>`은 컴포넌트의 스타일(CSS)을 정의하며, 여러 개 작성할 수 있고 `scoped` 속성을 붙이면 해당 컴포넌트에만 스타일이 적용되도록 범위를 제한할 수 있다.

**65**

| 배점 | 채점 요소                                                                                  |
| ---- | --------------------------------------------------------------------------------------------- |
| 2점  | public: 정적 파일 위치, import 없이 root 절대경로로 참조                                     |
| 2점  | src/assets: 프로젝트 내 이미지·폰트·스타일시트 등을 관리하며 컴포넌트에서 import하여 참조     |

**모범 답안**

> `public` 디렉토리는 정적 파일을 위치시키는 곳으로, 소스코드에서 import하지 않고 항상 root 기준 절대경로로 참조한다(예: `public/icon.png` → `/icon.png`). 반면 `src/assets`는 프로젝트 내에서 사용되는 이미지, 폰트, 스타일시트 등을 관리하며, 컴포넌트 내에서 import하여 참조하는 내부 자원이다. 즉 컴포넌트에서 직접 참조/가공해야 하는 자원은 assets에, 그대로 노출되기만 하면 되는 정적 파일은 public에 두는 것이 원칙이다.

| 배점 | 채점 요소                                                                                          |
| ---- | ----------------------------------------------------------------------------------------------------- |
| 1.5점 | index.html은 유일한 진입점이며 Root 컴포넌트(App.vue)가 이 페이지에 mount됨                         |
| 1.5점 | 화면 전환·데이터 변경은 서버에 새 HTML을 요청하지 않고 Vue(JS)가 DOM을 직접 갱신 → 이 구조 때문에 SPA로 동작 |

**모범 답안**

> Vite로 생성된 Vue 프로젝트에서 `index.html`은 앱의 유일한 진입점이며, Root 컴포넌트인 App.vue가 이 페이지에 mount된다. 즉 브라우저는 최초에 단 하나의 HTML 파일만 로드하고, 이후 화면 전환이나 데이터 변경은 모두 Vue(JavaScript)가 DOM을 직접 갱신하며 처리한다. 페이지 이동 시마다 서버로부터 새로운 HTML을 요청하지 않는 이러한 구조 때문에 Vue 앱은 자연스럽게 SPA로 동작하게 된다.

**67**

| 배점 | 채점 요소                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------ |
| 1점  | Composition API: import한 API 함수(ref, onMounted 등)로 로직을 정의, Vue3 권장 방식             |
| 1점  | Option API: data(), methods, mounted 같은 옵션 객체로 로직 정의, Vue2 방식(Vue3에서도 지원)     |
| 1점  | Composition API 권장 상황: 규모 있는 앱을 SFC와 함께 구축할 때                                  |
| 1점  | Option API 권장 상황: 빌드 도구 미사용 또는 복잡성 낮은 프로젝트                                |

**모범 답안**

> Composition API는 `ref`, `onMounted` 등 import해서 가져온 API 함수들을 사용해 컴포넌트의 로직을 정의하는 방식으로 Vue3에서 권장되는 방식이다. Option API는 `data()`, `methods`, `mounted` 같은 옵션 객체를 사용해 로직을 정의하는 방식으로 Vue2의 작성 방식이며 Vue3에서도 계속 지원된다. 권장 사항으로는, 규모가 있는 애플리케이션 전체를 SFC와 함께 구축하려는 경우에는 Composition API가 권장되며, 빌드 도구를 사용하지 않거나 복잡성이 낮은 프로젝트에서는 Option API 사용이 권장된다.

**68**

| 배점 | 채점 요소                                                                                       |
| ---- | ---------------------------------------------------------------------------------------------------- |
| 1점  | scoped 사용 시 현재 컴포넌트 내부에만 스타일 적용되어 유출/침범 방지                                 |
| 1점  | scoped 미사용 시 전역적으로 영향을 미쳐 다른 컴포넌트에도 의도치 않게 스타일 적용 가능               |
| 2점  | 예외: 자식 컴포넌트의 최상위 요소에는 부모의 scoped 스타일도 영향을 줄 수 있음을 예시와 함께 설명   |

**모범 답안**

> `<style scoped>`를 사용하면 해당 스타일은 현재 컴포넌트 내부 요소에만 적용되어 다른 컴포넌트로의 스타일 유출/침범을 막는다. scoped를 사용하지 않으면 해당 스타일은 전역적으로 영향을 미쳐, 다른 컴포넌트에서 같은 태그(예: div)를 사용할 경우 의도치 않게 스타일이 함께 적용될 수 있다. 예외적으로, 자식 컴포넌트의 "최상위 요소(root element)"에 한해서는 부모 컴포넌트의 scoped 스타일도 영향을 줄 수 있다. 예를 들어 App.vue에 `<style scoped> div { color: red; } </style>`가 있고, 자식 MyComponent.vue의 최상위 요소가 `<div>`라면, 그 안의 `<h2>MyComponent</h2>` 텍스트는 부모의 스타일 영향을 받아 빨간색으로 표시된다. 이는 Vue가 부모 컴포넌트에서 자식 컴포넌트의 레이아웃(배치)을 쉽게 제어할 수 있도록 의도적으로 허용한 동작이다.

| 2점  | SPA(CSR)는 콘텐츠가 JS 실행 이후 렌더링되어 검색엔진이 콘텐츠를 분석하기 어려운 SEO 문제가 있음    |

| 1점  | React 진영의 SSR 지원 프레임워크: Next.js                                                          |

**모범 답안**

| 배점 | 채점 요소                                                                                    |

| 1점  | `npm install`은 항상 프로젝트 루트 디렉토리에서 실행해야 함                                      |
| 1점  | node_modules는 필요할 때마다 재생성 가능하므로 직접 수정하거나 Git으로 관리할 필요 없음           |

**모범 답안**

> 첫째, `npm install`은 항상 프로젝트 루트 디렉토리(프로젝트를 생성한 폴더)에서 실행해야 한다. 둘째, node_modules 폴더는 필요할 때마다 `npm install`로 재생성 가능하므로 직접 수정하거나 Git으로 관리할 필요가 없다. 셋째, package.json과 package-lock.json은 직접 편집을 자제하고 `npm install 패키지명` 명령을 통해 자동으로 업데이트하는 것이 안전하다. 넷째, 패키지 버전 충돌이나 이상 동작이 의심될 경우 node_modules 폴더를 삭제한 뒤 다시 `npm install`을 실행하는 재설치를 고려할 수 있다.

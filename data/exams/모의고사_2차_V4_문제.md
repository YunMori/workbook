## Ⅰ. 객관식 (각 3점, 총 63점)

**1. [기초]** ECMAScript와 JavaScript의 관계로 옳은 것은?

① ECMAScript는 표준화된 스크립트 언어의 **명세**이고, JavaScript는 그 표준을 구현한 언어이다.
② ECMAScript는 JavaScript를 실행하는 런타임 환경이다.
③ JavaScript는 ECMAScript의 상위 호환 명세이다.
④ 둘은 서로 다른 언어이며 문법적 연관이 없다.

---

**2. [기초]** JavaScript 식별자(변수명) 작성 규칙으로 **옳지 않은** 것은?

① 반드시 문자, `$`, `_` 중 하나로 시작해야 한다.
② 대소문자를 구분한다.
③ 숫자로 시작하는 이름도 따옴표로 감싸면 사용할 수 있다.
④ 예약어(`for`, `if`, `function` 등)를 사용할 수 없다.

**3. [응용]** 다음 코드의 출력 결과를 순서대로 나열한 것은?

```js
let x = 1
if (x === 1) {
  let x = 2
  console.log(x)
}
console.log(x)
```

① 1, 1  ② 2, 1  ③ 2, 2  ④ `SyntaxError` 발생

**4. [기초]** 함수 선언식과 표현식의 비교로 옳은 것은?

① 선언식은 익명 함수 사용이 가능하고 호이스팅되지 않는다.
② 표현식은 호이스팅되므로 정의 전에 호출할 수 있다.
③ 선언식이 사용 권장 방식이다.
④ 표현식은 익명 함수 사용이 가능하고 호이스팅되지 않으며, 사용이 권장된다.

**8. [기초]** `v-if`와 `<template>` 요소의 사용에 대한 설명으로 **옳지 않은** 것은?

① `<template>`에 `v-if`를 사용하면 여러 요소에 조건을 한 번에 적용할 수 있다.
② `v-else`, `v-else-if`도 `<template>`에 적용할 수 있다.
③ `<template>` 태그 자체는 렌더링 결과에 남지 않는다.
④ `<template>`은 "보이지 않는 wrapper" 역할을 하며 렌더링 시 `<div>`로 변환된다.

**10. [응용]** 다음 중첩 `v-for` 코드에 대한 설명으로 옳은 것은?

```html
<ul v-for="item in myInfo">
  <li v-for="friend in item.friends">
    {{ item.name }} - {{ friend }}
  </li>
</ul>
```

① 각 `v-for` 범위는 상위 범위에 접근할 수 있으므로 정상 동작한다.
② 내부 `v-for`에서는 외부 `v-for`의 `item`에 접근할 수 없다.
③ 중첩 `v-for`는 2단계까지만 허용된다.
④ 중첩 `v-for`에서는 `key`를 작성할 수 없다.

② JavaScript를 컴파일하여 기계어로 변환하는 컴파일러이다.
③ Vue 프로젝트의 번들러이다.

**12. [기초]** `package.json`과 `package-lock.json`에 대한 설명으로 **옳지 않은** 것은?

① `package.json`은 프로젝트의 메타 정보와 의존성 패키지 목록을 포함한다.
② 두 파일 모두 직접 편집하여 버전을 관리하는 것이 권장된다.
③ `package-lock.json`은 패키지의 실제 설치 버전, 의존성 관계, 하위 패키지 정보를 포함한다.
④ `package-lock.json`은 협업 시 일관성 있는 의존성 유지에 도움을 준다.

**13. [응용]** `public` 디렉토리와 `src/assets` 디렉토리의 용도 구분으로 옳은 것은?

① `public` — 소스코드에서 참조되지 않고 import가 필요 없는 정적 파일 / `src/assets` — 컴포넌트 자체에서 참조하는 내부 파일
② `public` — 컴포넌트 자체에서 참조하는 내부 파일 / `src/assets` — import가 필요 없는 정적 파일
③ 두 디렉토리는 기능적으로 완전히 동일하다.
④ `public`은 빌드 시 삭제되는 임시 디렉토리이다.

**14. [기초]** 부모가 내려보낸 props를 자식 컴포넌트에서 사용하기 위해 필요한 것은?

① 부모 컴포넌트에서 `defineEmits()` 선언
② `main.js`에 전역 등록
③ 자식 컴포넌트에서 `defineProps()`를 사용한 명시적인 props 선언
④ 별도 선언 없이 항상 자동으로 사용 가능

**15. [응용]** `App > Parent > ParentChild > ParentGrandChild` 구조에서 `ParentGrandChild`가 `Parent`의 데이터 변경을 요청하려 할 때 옳은 설명은?

① `emit`은 컴포넌트 깊이에 상관없이 한 번에 최상위까지 전달된다.
② `ParentGrandChild`에서 props를 직접 수정하면 된다.
③ `$emit`은 `<script setup>`에서 직접 호출할 수 있으므로 중간 단계가 필요 없다.
④ `emit`은 한 단계씩 위로 전달해야 하므로 `ParentChild`가 이벤트를 수신 후 다시 발신해야 한다.

**16. [기초]** Lifecycle Hooks에 대한 설명으로 **옳지 않은** 것은?

① Vue 인스턴스의 생애주기 동안 특정 시점에 실행되는 함수이다.
② hooks 함수들은 반드시 비동기적으로 작성되어야 한다.
③ Vue는 hooks에 등록된 콜백 함수들을 인스턴스와 자동으로 연결한다.
④ 가장 일반적으로 사용되는 것은 `onMounted`, `onUpdated`, `onUnmounted`이다.

① `watch([foo, bar], ([newFoo, newBar], [prevFoo, prevBar]) => {})`
② `watch(foo, bar, (newVal, oldVal) => {})`
③ `watch({ foo, bar }, (newVal) => {})`
④ `watch(foo && bar, (newVal) => {})`

**18. [기초]** Pinia의 Setup Store에 대한 설명으로 **옳지 않은** 것은?

① store는 공유하지 않는 private한 상태 속성을 별도로 가질 수 있다.
② `defineStore()`의 첫 번째 인자는 애플리케이션 전체에서 사용하는 store의 고유 ID이다.
③ `defineStore()` 반환 값의 이름은 `use`와 `store`를 붙여 짓는 것이 권장된다.
④ store의 상태를 사용하려면 반드시 반환(`return`)해야 한다.

**19. [응용]** Nested Routes 설정에 대한 설명으로 **옳지 않은** 것은?

① `children` 옵션에 배열 형태로 중첩 관계를 표현한다.
② 중첩된 Named Routes는 일반적으로 하위 경로에만 이름을 지정한다.
③ 중첩 라우팅은 반드시 컴포넌트의 부모-자식 관계와 일치해야만 사용할 수 있다.
④ 부모 컴포넌트 내부에도 `<RouterView />`를 작성해야 자식이 렌더링된다.

**21. [기초]** Axios의 `then`과 `catch`에 대한 설명으로 옳은 것은?

① `then`은 요청이 실패했을 때 실행된다.
② `then`은 요청이 성공하면 실행되며, callback은 이전 작업의 성공 결과를 인자로 전달받는다.
③ `catch`가 실행된 뒤에도 남아 있는 `then`들이 모두 정상 실행된다.
④ axios로 처리한 비동기 로직은 promise 객체를 반환하지 않는다.

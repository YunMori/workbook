## 객관식 해설

**1. 정답 ②** — `for`문의 `i`는 매 반복마다 값이 재할당되므로 `const`로 선언하면 에러가 발생한다. (1_js_dom_and_event §1)

**2. 정답 ②** — `for...in`/`for...of`는 재할당이 아니라 매 반복마다 다른 속성 이름/값이 변수에 새로 지정되는 방식이라 `const` 사용이 가능하다. (1_js_dom_and_event §2)

**3. 정답 ③** — `while`, `for`, `for...in`, `for...of` 반복문 모두 블록 스코프를 갖는다. (1_js_dom_and_event §3)

**4. 정답 ④** — 슬라이드에서 언급된 JS 실행 환경은 script 태그 내부 작성, 별도 js 파일 연결, 브라우저 콘솔 3가지다. (1_js_dom_and_event §4)

**5. 정답 ④** — DOM은 CSS만이 아니라 HTML 문서 전체(구조, 스타일, 내용)를 객체로 표현하는 모델이다. (1_js_dom_and_event §5)

**6. 정답 ②** — DOM의 모든 요소, 속성, 텍스트는 하나의 객체이며 모두 `document` 객체의 하위 객체로 구성된다. (1_js_dom_and_event §6)

**7. 정답 ②** — 브라우저는 HTML 문서를 해석해 DOM tree라는 객체 트리로 구조화하며, 객체 간 상속 구조를 가진다. (1_js_dom_and_event §7)

**8. 정답 ③** — `document.title`에 값을 재할당하면 실제 HTML `<title>`이 변경되어 브라우저 탭 제목도 바뀐다. (1_js_dom_and_event §8)

**9. 정답 ②** — DOM 조작은 "조작하고자 하는 요소를 선택(탐색)"한 뒤 "선택된 요소의 콘텐츠 또는 속성을 조작"하는 순서로 이루어진다. (1_js_dom_and_event §9)

**10. 정답 ②** — `querySelector`는 CSS selector를 만족하는 첫 번째 element를 반환하고, 없으면 `null`을 반환한다. (1_js_dom_and_event §10)

**11. 정답 ③** — `querySelectorAll`은 조건을 만족하는 요소들을 `NodeList` 형태로 반환한다. (1_js_dom_and_event §11)

**12. 정답 ②** — `querySelectorAll()`로 반환된 NodeList는 이후 DOM이 변경되어도 값이 바뀌지 않는(non-live) 정적 목록이다. (1_js_dom_and_event §12)

**13. 정답 ④** — 슬라이드에서 제시한 DOM 조작 4가지는 속성 조작, HTML 콘텐츠 조작, DOM 요소 조작, 스타일 조작이다. (1_js_dom_and_event §13)

**14. 정답 ③** — `classList`는 요소의 클래스 목록을 유사 배열인 `DOMTokenList` 형태로 반환한다. (1_js_dom_and_event §14)

**15. 정답 ②** — `toggle()`은 클래스가 존재하면 제거하고 `false`를 반환하며, 존재하지 않으면 추가하고 `true`를 반환한다. (1_js_dom_and_event §15)

**16. 정답 ②** — `getAttribute(name)`은 해당 요소에 지정된 속성 값을 조회하여 반환한다. (1_js_dom_and_event §16)

**17. 정답 ③** — `removeAttribute`로 속성을 제거한 뒤 `getAttribute`로 재조회하면 `null`이 반환된다. (1_js_dom_and_event §17)

**18. 정답 ②** — `textContent`는 HTML 마크업을 해석하지 않고 순수 문자열(텍스트)만 처리한다는 점에서 `innerHTML`과 구분된다. (1_js_dom_and_event §18)

**19. 정답 ②** — `innerHTML`은 문자열을 HTML로 해석/렌더링하므로 사용자 입력을 그대로 넣으면 XSS 공격에 취약해질 수 있다. (1_js_dom_and_event §19)

**20. 정답 ①** — `createElement(tagName)`은 지정한 태그명의 HTML 요소를 새로 생성해 반환하며, 이 시점에는 아직 DOM에 삽입되지 않는다. (1_js_dom_and_event §20)

**21. 정답 ②** — `appendChild()`는 특정 부모 Node의 자식 목록 마지막에 Node를 삽입하며, 추가된 Node 객체를 반환한다. (1_js_dom_and_event §21)

**22. 정답 ③** — `removeChild()`는 DOM에서 자식 Node를 제거하고, 제거된 Node를 반환한다. (1_js_dom_and_event §22)

**23. 정답 ④** — 슬라이드에서 언급된 Node 종류는 Document Node, Element Node, Text Node, Attribute Node이다. (1_js_dom_and_event §23)

**24. 정답 ④** — `querySelectorAll()`이 반환하는 NodeList는 DOM 변경사항을 실시간 반영하지 않는다(non-live). (1_js_dom_and_event §24)

**25. 정답 ②** — Element는 Node의 하위 유형으로, HTML 요소를 나타내는 특별한 Node이다. 따라서 모든 Element는 Node지만 역은 성립하지 않는다. (1_js_dom_and_event §25)

**26. 정답 ②** — Parsing(구문 분석/해석)은 브라우저가 문자열을 해석하여 DOM Tree로 만드는 과정이며, 이후 Style → Layout 순으로 진행된다. (1_js_dom_and_event §26)

**27. 정답 ②** — 함수는 참조 자료형에 속하며, 모든 함수는 Function object이다. (1_js_dom_and_event §27)

**28. 정답 ④** — 원시 자료형은 Number, String, Boolean, null, undefined이며, Array는 참조 자료형(Object)에 속한다. (1_js_dom_and_event §28)

**29. 정답 ②** — 함수 본문에 `return` 값이 없다면 `undefined`가 반환된다. (1_js_dom_and_event §29)

**30. 정답 ②** — 함수 선언식은 호이스팅되어 정의 전에 호출해도 동작하지만, 함수 표현식은 호이스팅되지 않아 정의 전에 호출하면 `ReferenceError`가 발생한다. (1_js_dom_and_event §30)

**31. 정답 ③** — 함수 표현식은 호이스팅되지 않으므로 정의 전에 접근하면 `ReferenceError`가 발생한다. (1_js_dom_and_event §31)

**32. 정답 ②** — 슬라이드는 함수 선언식과 표현식을 비교한 뒤 "표현식 사용 권장"이라고 강조한다. (1_js_dom_and_event §32)

**33. 정답 ①** — 기본 매개변수는 전달하는 인자가 없거나 `undefined`가 전달될 경우 지정한 기본값으로 초기화된다. (1_js_dom_and_event §33)

**34. 정답 ③** — 나머지 매개변수는 함수당 하나만 작성 가능하고 반드시 마지막 매개변수 자리에 위치해야 하며, `...restParams` 형태로 배열을 만든다. (1_js_dom_and_event §34)

**35. 정답 ②** — 매개변수 개수가 인자 개수보다 많으면 누락된 인자는 `undefined`로 할당된다. (1_js_dom_and_event §35)

**36. 정답 ①** — Spread syntax는 배열이나 문자열처럼 반복 가능한 항목을 펼치는(전개하는) 구문이다. (1_js_dom_and_event §36)

**37. 정답 ②** — 객체를 바로 반환하려면 소괄호로 감싸야 한다. 그냥 중괄호만 쓰면 함수 블록으로 해석되어 오류가 발생한다. (1_js_dom_and_event §37)

**38. 정답 ②** — JS는 문장 마지막 세미콜론이 선택적이며, ASI에 의해 자동으로 삽입된다. (1_js_dom_and_event §38)

**39. 정답 ③** — `var`는 블록 스코프가 아니라 함수 스코프를 가지며, 이 때문에 ES6 이후로는 `const`/`let` 사용이 권장된다. (1_js_dom_and_event §39)

**40. 정답 ③** — 화살표 함수는 자신만의 `this`가 없어 상위 스코프의 `this`(전역, 즉 `window`)를 그대로 사용한다. (1_js_dom_and_event §40)

## 주관식 해설

**41.** HTMLCollection

- 구식 선택자들은 실시간으로 DOM 변경을 반영하는 HTMLCollection을 반환한다(`querySelectorAll`의 NodeList와 대비됨).

**42.** document

- `document` 객체는 웹 페이지 객체이자 DOM Tree의 진입점이다.

**43.** setAttribute(name, value)

- 속성이 이미 있으면 값을 갱신하고, 없으면 새로 추가한다.

**44.** appendChild()

- `parent.appendChild(child)`로 자식 목록의 마지막에 요소를 삽입한다.

**45.** Style → Layout

- 슬라이드는 Parse → Style → Layout 순서의 다이어그램을 제시한다.

**46.** 익명 함수

- 함수 표현식은 이름이 없는 익명 함수를 사용할 수 있다는 점이 선언식과의 차이다.

**47.** 사용하지 않는다(무시된다)

- 매개변수 개수 < 인자 개수인 경우 초과 입력한 인자는 사용하지 않는다.

**48.** 나머지 매개변수(Rest parameters)

- `...restParams` 형태로 작성하며 하나만, 마지막 위치에만 쓸 수 있다.

**49.** Spread syntax(전개 구문)

- 배열이나 문자열 같은 반복 가능한 항목을 펼치는 구문이다.

**50.** 소괄호 `()`

- 매개변수가 하나면 `()`를 생략할 수 있으나, 슬라이드는 생략하지 않는 것을 권장한다고 언급한다.

**51.** Cannot access '변수명' before initialization (ReferenceError)

- `var`와 달리 `let`/`const`는 선언 전 참조 시 `undefined`가 아니라 `ReferenceError`가 발생한다.

**52.** var (암묵적 전역 변수)

**53.** event object (이벤트 객체)

**54.** event handler(이벤트 처리기)

**55.** 문자열(string)

- 예: `'click'`처럼 수신할 이벤트 이름을 문자열로 작성한다.

**56.** 이벤트 버블링(Event Bubbling)

- 가장 최상단 조상 요소(document)를 만날 때까지 반복된다.

**57.** event.currentTarget

- `this`와 동일한 값을 가지며, 버블링 중에도 값이 바뀌지 않는다(핸들러가 부착된 요소로 고정).

**58.** event.target

- 버블링이 진행되어도 값이 변하지 않고 최초 발생 지점을 유지한다.

**59.** event.preventDefault()

**60.** textContent

## 서술형 채점 기준

**61**

| 배점 | 채점 요소                                                                        |
| ---- | -------------------------------------------------------------------------------- |
| 2점  | `querySelector()`는 조건을 만족하는 첫 번째 요소 하나만 반환, 없으면 `null` 반환 |
| 2점  | `querySelectorAll()`은 조건을 만족하는 모든 요소를 `NodeList` 형태로 반환        |

**모범 답안**

> `querySelector()`는 제공한 CSS selector를 만족하는 요소 중 첫 번째 요소 하나만 반환하며, 해당하는 요소가 없으면 `null`을 반환한다. 반면 `querySelectorAll()`은 조건을 만족하는 모든 요소를 `NodeList` 형태로 반환한다. 즉 하나는 단일 요소 선택용, 다른 하나는 다중 요소 선택용이라는 점이 핵심 차이다.

---

**62**

| 배점 | 채점 요소                                                                                      |
| ---- | ---------------------------------------------------------------------------------------------- |
| 2점  | `innerHTML`은 문자열을 HTML 마크업으로 해석·렌더링하며, 사용자 입력을 그대로 넣으면 XSS에 취약 |
| 2점  | `textContent`는 문자열을 순수 텍스트로만 처리하고 태그를 해석하지 않아 안전                    |

**모범 답안**

> `innerHTML`은 대입한 문자열을 HTML 마크업으로 해석하여 실제 태그로 렌더링하기 때문에, 사용자 입력값을 그대로 넣으면 악성 스크립트가 실행되는 XSS(Cross-Site Scripting) 공격에 취약해질 수 있다. 반면 `textContent`는 문자열을 순수 텍스트로만 처리하고 태그를 해석하지 않으므로 안전하게 텍스트 내용을 표시하거나 변경할 때 사용한다. 따라서 사용자 입력을 화면에 표시할 때는 가능한 `textContent`를 사용하는 것이 안전하다.

**63**

| 배점 | 채점 요소                                                                                   |
| ---- | ------------------------------------------------------------------------------------------- |
| 1점  | Node는 DOM의 기본 구성 단위로 문서 전체, 요소, 텍스트, 속성이 모두 Node 객체로 표현됨       |
| 1점  | Element는 Node의 하위 유형으로 HTML 요소를 나타내는 특별한 Node                             |
| 1점  | 모든 Element는 Node이지만, 모든 Node가 Element인 것은 아님(Text/Attribute Node 등 존재)     |
| 1점  | NodeList는 Node들을 모아놓은 배열과 유사한 목록으로, index 접근 가능하나 실시간 반영은 아님 |

**모범 답안**

> Node는 DOM의 기본 구성 단위로, DOM 트리의 각 부분(문서 전체, 요소, 텍스트, 속성)이 모두 Node 객체로 표현된다. Element는 Node의 하위 유형으로 `<p>`, `<div>` 같은 HTML 요소를 나타내는 특별한 Node이며, `className`, `innerHTML` 등 요소 특화 기능을 추가로 가진다. 따라서 모든 Element는 Node이지만, Text Node나 Attribute Node처럼 Element가 아닌 Node도 있으므로 모든 Node가 Element인 것은 아니다. NodeList는 이러한 Node들을 DOM 선택 메서드로 모아놓은 배열과 유사한 목록으로, index로 접근 가능하지만 실시간으로 DOM 변경을 반영하지는 않는다(querySelectorAll 기준).

**64**

| 배점  | 채점 요소                                                             |
| ----- | --------------------------------------------------------------------- |
| 1.5점 | 함수 선언식은 호이스팅되어 정의 전 호출도 정상 동작                   |
| 1.5점 | 함수 표현식은 호이스팅되지 않아 정의 전 호출 시 `ReferenceError` 발생 |
| 1점   | 슬라이드는 표현식 사용을 권장한다는 언급                              |

**모범 답안**

> 함수 선언식(`function funcName() {...}`)은 코드 실행 전 호이스팅되어 정의보다 앞선 위치에서 호출해도 정상 동작한다. 반면 함수 표현식(`const funcName = function() {...}`)은 변수 할당 형태이기 때문에 호이스팅되지 않으며, 정의 이전에 호출하면 `ReferenceError: Cannot access 'funcName' before initialization`이 발생한다. 또한 함수 표현식은 이름 없는 익명 함수를 사용할 수 있다는 차이도 있다. 슬라이드는 예기치 못한 호출 순서 문제를 줄이기 위해 표현식 사용을 권장한다.

**65**

| 배점  | 채점 요소                                                                    |
| ----- | ---------------------------------------------------------------------------- |
| 1.5점 | 기본 매개변수: 인자 미전달/undefined 시 기본값으로 초기화, 예시 포함         |
| 1.5점 | 나머지 매개변수: 임의 개수 인자를 배열로 모음, 하나만·마지막 위치, 예시 포함 |

**모범 답안**

> 기본 함수 매개변수는 인자가 전달되지 않거나 `undefined`가 전달될 때 매개변수를 미리 지정한 기본값으로 초기화하는 방식이다. 예를 들어 `function greeting(name = 'Anonymous') { return \`Hi ${name}\` }`는 `greeting()`호출 시`'Hi Anonymous'`를 반환한다. 반면 나머지 매개변수는 정해지지 않은 개수의 인자를 하나의 배열로 모아 받는 방식으로, `...restParams`처럼 작성하며 함수당 하나만, 반드시 매개변수 목록의 마지막에만 위치할 수 있다. 예를 들어 `function myFunc(a, b, ...rest) {...}`를 `myFunc(1,2,3,4)`로 호출하면 `rest`는 `[3,4]`가 된다.

| 1.5점 | 일반 함수: `this`가 이벤트 대상 요소(`event.currentTarget`)를 가리킴                   |
| 1.5점 | 화살표 함수: 자신만의 `this`가 없어 상위 스코프(전역, `window`)의 `this`를 그대로 참조 |

**모범 답안**

> 일반 함수로 콜백을 작성하면 `addEventListener`가 해당 함수를 호출할 때 `this`를 이벤트가 부착된 요소(즉 `event.currentTarget`)로 바인딩해주므로, 콜백 내부의 `this`는 버튼과 같은 대상 요소를 가리킨다. 반면 화살표 함수는 자기 자신만의 `this`를 갖지 않고 자신을 감싸는 상위 스코프의 `this`를 그대로 참조(상속)하기 때문에, 전역 스코프에서 정의된 화살표 함수라면 `this`는 대상 요소가 아니라 `window`를 가리키게 된다. 따라서 이벤트 핸들러 안에서 대상 요소를 `this`로 참조해야 하는 경우에는 화살표 함수 대신 일반 함수를 사용해야 한다.

| 배점  | 채점 요소                                                                        |

| 1.5점 | 이벤트 버블링 정의: 발생 요소 → 부모 → 최상단(document)까지 핸들러가 순차 실행   |
| 1점   | `event.currentTarget`은 핸들러가 부착된 요소로 고정                              |
| 1.5점 | `event.target`은 실제 이벤트 발생 지점(가장 안쪽 요소)이며, 중첩 div 예시로 설명 |

**모범 답안**

> 이벤트 버블링은 한 요소에서 이벤트가 발생하면 그 요소의 핸들러가 먼저 실행되고, 이어서 부모 요소, 조상 요소 순으로 최상단(document)까지 핸들러가 순차적으로 실행되는 현상이다. `outerouter > outer > inner` 구조에서 `outerouter`에만 핸들러를 부착했다고 할 때, `inner`를 클릭하면 이벤트가 버블링되어 `outerouter`의 핸들러가 실행되지만, 이때 `event.currentTarget`은 핸들러가 부착된 `outerouter`로 항상 고정되는 반면, `event.target`은 실제로 클릭이 발생한 가장 안쪽 요소인 `inner`를 가리킨다. 즉 `currentTarget`은 핸들러 부착 위치, `target`은 이벤트 발생 위치라는 점이 핵심 차이다.

**70**

| 배점  | 채점 요소                                                               |
| ----- | ----------------------------------------------------------------------- |
| 1.5점 | `var`: 함수 스코프, 선언 전 참조 시 호이스팅으로 `undefined` 반환       |
| 1.5점 | `let`/`const`: 블록 스코프, 선언 전 참조 시 TDZ로 `ReferenceError` 발생 |
| 1점   | ES6 이후 `let`/`const` 권장 이유(스코프 제한, 버그 방지)                |

**모범 답안**

> `var`는 함수 스코프(function scope)를 가지므로 블록({}) 내부에서 선언해도 함수 전체 범위에서 접근 가능하며, 선언 이전에 참조하면 호이스팅으로 인해 `undefined`가 반환된다. 반면 `let`/`const`는 블록 스코프를 가져 선언된 블록 내부에서만 유효하고, 선언 이전에 참조하면 TDZ(일시적 사각지대)로 인해 `ReferenceError: Cannot access '변수명' before initialization`이 발생한다. `var`는 재선언·재할당이 자유롭고 함수 스코프 특성 때문에 의도치 않게 변수가 덮어써지거나 스코프 밖에서 접근되는 등 예기치 못한 버그를 유발하기 쉬워, ES6 이후에는 변수의 스코프를 명확히 제한하고 실수를 줄일 수 있는 `const`/`let` 사용이 권장된다.
